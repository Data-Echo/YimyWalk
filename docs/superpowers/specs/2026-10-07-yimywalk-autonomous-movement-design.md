# YimyWalk 主动运动与角色预览设计

## 背景

当前 Core 已有 `Jump`、`Apex`、`Fall` 状态和窗口顶部落脚选择，但主动跳跃没有接入自动行为。桌面边缘仍然只支持跨屏，管理页预览使用固定渲染尺寸，较大的 sprite 会被裁切。默认角色包还同时包含猫咪和史莱姆。

本次改动覆盖五个需求：默认只提供史莱姆并使用指定优化图像；加入低频主动跳跃和跳跃欲望设置；允许落到可见窗口顶部时主动寻找前方窗口；加入屏幕侧边攀爬、顶部行走和释放下落；修正 idle1 预览的自适应缩放。

## 已确认的行为约束

- 默认角色只保留 `slime`，仓库和发布包不再带 `cat`。
- 跳跃欲望和攀爬欲望都使用“全局默认值 + 单只桌宠覆盖”。
- 跳跃欲望默认 20%，攀爬欲望默认 12%，范围均为 0–100%。0% 禁止对应的主动行为；数值越高只提高低频尝试概率，不代表每帧抽签。
- 可见窗口顶部目标按当前行走方向选择前方最近的可到达窗口；没有合适目标时执行普通主动跳跃。
- 攀爬独立于跳跃欲望，走到显示器工作区侧边后按攀爬欲望尝试；未触发时保留穿屏。
- 攀爬到屏幕顶部下方的安全落脚点后进入顶部行走；顶部行走可以低频释放并进入普通下落，最终回到屏幕底部。
- 管理页桌宠预览只显示选中角色的 idle1（3×3 sprite 的索引 0），完整保持比例并根据控件可用宽高自动缩小或放大，不裁切、不引入滚动条。

## 方案与边界

采用在现有 Core 物理状态机上扩展的方案。Core 负责可测试的状态、冷却、目标选择和位置推进；Windows 层只负责提供显示器与可见窗口候选，以及把 Core 状态渲染成现有帧。不会在 AppHost 定时器里直接注入未经 Core 验证的位移，也不会重写跨屏、拖拽和资源租约体系。

## 核心模型

### 设置与单只覆盖

`SettingsDocument` 增加：

- `JumpDesire`：默认 `0.20f`，范围 `[0, 1]`。
- `ClimbDesire`：默认 `0.12f`，范围 `[0, 1]`。

`PetSession`/`PetEngine` 暴露经过范围限制的全局值，`AppHost` 在启动、修改和保存设置时同步它们。旧的 schema-v1 JSON 缺少新字段时使用默认值，不改变现有文件的读取兼容性。

`PetBehaviorOverrides` 增加 `JumpDesireOverride` 和 `ClimbDesireOverride` 两个可空值，并提供解析方法。`Inherit` 使用全局值，覆盖值限制在 `[0, 1]`；无穷、NaN 和越界值回退到安全默认值。管理器桌宠页沿用已有的继承/覆盖编辑模式。

### 自动行为调度

每个 `PetInstance` 保存自己的主动行为冷却时间，避免所有实例同步跳跃，也避免每个 16ms Tick 重复抽签。冷却随行为完成或被打断时重置；欲望为 0 时不进行对应行为尝试。拖拽、Eat、Jump、Apex、Fall 和已在攀爬状态时不触发新的主动行为。

主动行为只在 `Idle`/`Walk` 的稳定落脚状态尝试：

1. 检查对应欲望和冷却。
2. 用注入的 `IRandomSource` 做低频尝试。
3. 跳跃先询问当前表面是否有可到达的前方窗口目标；有则使用目标方向的水平速度，没有则使用普通跳跃水平速度。
4. 行为开始后设置新的冷却，直到落地、释放下落或被用户拖拽中断。

### 窗口顶部目标

在 Core 增加平台无关的目标选择入口，复用现有 `WindowSurfaceCandidate` 过滤条件。候选必须可见、未最小化、未排除、未过期、未遮挡、未最大化、宽高有效，并位于当前行走方向的前方和当前可达高度范围内。按水平距离和当前朝向选择最近候选；窗口顶部落脚仍由现有 `SurfaceSelector` 负责最终承接。

当 `WindowLandingEnabled` 关闭时，不生成窗口主动跳跃目标；现有普通重力、拖拽抛掷和屏幕底部行为不变。

### 侧边攀爬与顶部行走

扩展 `PetState` 增加攀爬和顶部行走所需的明确状态。进入攀爬前记录当前显示器工作区和边缘方向：

- 右边缘固定 X，左边缘固定 X，Y 按攀爬速度向工作区顶部推进。
- 顶部落脚点使用角色锚点和帧高度留出安全上边距，保证精灵最高点位于屏幕最上方之下。
- 到达顶部后进入顶部行走，沿顶部水平移动并保持同一边缘坐标约束解除后的方向。
- 顶部行走按独立低频释放规则切换为 `Fall`，水平速度归零，沿当前显示器或全局水平边界下落到底部。
- 如果到达边缘但没有触发攀爬，继续沿用现有跨屏循环；窗口表面边缘不触发屏幕攀爬。

攀爬和顶部行走使用走路帧（包含朝向翻转）；跳跃、顶点和下落仍使用既有第 6、7、8 帧映射。拖拽释放、显示器丢失和窗口表面选择优先级高于自动攀爬。

## 应用层与资源

- 将用户指定路径中的优化史莱姆 PNG 复制到当前仓库 `Characters/slime/sprite.png`，删除 `Characters/cat`，并让发布脚本从清理后的角色根目录复制。发布目录先清理，防止旧 cat 文件残留。
- `AppHost` 读取并保存两个全局欲望值，把它们传给 `PetSession`；角色选择回退顺序固定为 `slime` 优先，若自定义角色存在则继续支持扫描和手动选择。
- `SettingsPage` 增加两个全局欲望控件和说明；`PetsPage` 增加两个单只继承/覆盖控件，保持现有设置自动保存和重置语义。
- `CharacterFramePreview` 使用 idle1 的索引 0，并将图片显示模式改为按控件宽高等比缩放。缓存仍保留角色租约，不复制或修改源图像。

## 错误处理与兼容性

- 新设置字段缺失使用默认值；字段不是有限数字或越界时拒绝整个设置文档并按现有备份/默认恢复流程处理。
- 角色 PNG 继续使用现有 3×3、透明通道、尺寸和像素上限校验；优化史莱姆图像必须通过同一加载器。
- 窗口枚举失败、显示器快照无效或目标窗口在跳跃期间消失时回退到屏幕工作区和普通下落，不阻塞主循环。
- 不新增联网、自启动、快捷方式移动或管理员权限。

## 验证策略

先按 TDD 为每项新增行为写可重复 Core 测试，并观察测试在实现前失败：

- 设置默认值、范围验证、序列化往返和旧配置兼容。
- 单只跳跃/攀爬覆盖的继承、覆盖和重置。
- 主动跳跃欲望为 0 时不跳、低频冷却不连续触发、落地后冷却重置。
- 前方窗口目标选择、关闭窗口落脚时不选目标、候选过滤和目标消失回退。
- 左右侧攀爬、顶部安全点、顶部释放下落、未触发时跨屏回归。
- idle1 选择索引 0；高分辨率帧的预览控件使用 Zoom 适配，不改变缓存内容。

然后运行：

- `dotnet test YimyWalk.sln --configuration Release --no-restore`
- `dotnet build src/YimyWalk.App/YimyWalk.App.csproj -c Release -p:Platform=x64`
- 发布脚本和发布包自检，确认只包含 slime 与优化 PNG 的 SHA-256。
- 可用 Windows 桌面上的真实输入 smoke，观察主动跳跃、窗口顶部跳跃、侧边攀爬、释放下落和高分辨率 idle1 预览。没有实际硬件或桌面条件覆盖的显示器/DPI 矩阵继续明确标记为未验证。

## 不在本次范围

- 不增加角色动作素材格式；跳跃、攀爬和下落继续复用基础 3×3 帧。
- 不改变虚拟食物、对白、托盘、拖拽抛掷和资源租约的既有交互。
- 不把单只覆盖写入持久化设置文件；覆盖只在本次运行中有效，和现有桌宠实例覆盖一致。
