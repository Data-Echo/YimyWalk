# YimyWalk M1 设计（已批准，附条件）

批准日期：2026-10-04。批准范围和附加条件已转入实施计划 `docs/superpowers/plans/2026-10-04-yimywalk-m1-implementation.md`。

## 范围

M1 只完成：3×3 角色加载；发呆、行走、跳跃、坠落；屏幕工作区地面；拖拽和抛掷；透明宠物显示；托盘生命周期；多实例创建和清空。窗口顶部落脚、饥饿、气泡、外部应用事件和真实快捷方式操作留到后续阶段。核心模拟测试是实现顺序，不能替代真实桌面功能验收。

M1 必须提供 1、10、50、100 只创建和一键清空的真实入口。至少带两套可使用测试角色；只有 `sprite.png` 的角色可以加载运行，换角色不需要修改代码。100 是性能测试档位和可配置保护值，不是永久产品上限。

## eSheep 复用与目标框架决策

M0 固定并审计上游 `Adrianotiger/desktopPet` 提交 `e2933305157a34818f47d238c74607593d81816d`，结果见 `docs/UPSTREAM_AUDIT.md`。原版 Portable 工程目标 .NET Framework 4.7.2；在补齐 NuGet 和精确引用程序集后，原项目仍因未使用的 `stdole` COMReference 在 x86/x64 均失败。移除该引用的隔离项目副本可以成功生成并通过上游运动、显示器和 WinForms 运行时测试；上游快照本身不修改。

M1 复用上游 `src/dotNet/FormPet.cs` 的窗口输入/拖拽/抛掷和窗口 API 经验、`FormPet.Motion.cs` 的拖拽中断/镜像缓存清理思路、`Animations.cs` 的资源索引思想，以及 `tests/MotionTests.cs`、`RuntimeMotionTests.cs` 的边界测试案例。M1 不直接复用上游 XML 角色协议、全局静态状态、联网下载、自启动、上游管理界面或逐宠物进程模型；窗口和行为会用 YimyWalk 分层接口重写。

新代码使用 `net8.0-windows` WinForms 宿主，核心库为不引用 WinForms 或 Windows 桌面 API 的 `net8.0` 类库。依据是当前 Windows 11 x64 已有 .NET 8 SDK/WindowsDesktop runtime，目标功能需要 Win32 分层窗口，且可以把可测试核心与宿主隔离；这不是立即升级或迁移上游运行时，上游快照仍保持原目标框架供审计。

## 宿主、窗口和资源边界

采用“一个宠物一个透明窗口、一个宿主进程管理全部宠物”的映射，先沿用上游已验证的逐宠物窗口思路；不为每只宠物启动进程，也不预先改成全屏覆盖层。窗口通过 Win32 layered window 绘制 ARGB 帧，并以 `WM_NCHITTEST` 根据 Alpha 分别验证透明区域点击穿透和实体命中；拖拽捕获、释放抛掷和 `WS_EX_NOACTIVATE` 不抢焦点分别测试。

`YimyWalk.Core` 只处理不可变角色数据、帧元数据、实例状态、物理和接口；PNG 由 `CharacterLoader` 解码为共享只读 RGBA 图像，平台绘制对象由 `YimyWalk.App` 的 renderer/cache 创建和释放。位置、速度、动作计时和需求数值只属于 `PetInstance`，不写入共享角色定义。

角色刷新先完整校验再替换目录索引；失败保留上一份可用定义。刷新成功后新实例使用新定义，现存实例继续持有旧定义。旧定义在没有实例引用和在途绘制引用后才释放；创建、删除、清空和退出都取消事件、停止计时器、销毁窗口并释放专属/共享资源。

## 验证边界

计划必须分别记录：代码已实现、构建通过、核心测试通过、Windows 桌面已验证、Windows 桌面未验证。桌面会话中要记录实际实例数、Windows 版本/架构、DPI/显示器、CPU、内存及可用句柄指标，并观察反复创建/清空后的资源趋势。不能因为核心或普通窗口测试通过就宣布桌面 M1 全部验收通过。
