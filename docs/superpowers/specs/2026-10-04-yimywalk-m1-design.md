# YimyWalk M1 设计草案

## 目标

在不依赖真实桌面窗口的情况下验证角色格式、实例物理和资源共享，再接入一个 Windows 宠物窗口。M1 只覆盖屏幕工作区地面、发呆/行走/跳跃/坠落、拖拽/抛掷、托盘生命周期和批量创建/清空；窗口顶部落脚、饥饿、气泡和真实快捷方式暂不进入 M1 验收。

## 方案

采用 .NET 8 `net8.0-windows` WinForms 宿主和不引用 WinForms 的 `YimyWalk.Core` 类库。`CharacterLoader` 将 3×3 PNG 解码为共享 `CharacterDefinition`；`PetEngine` 用注入的单调时钟、随机源和 `IWorldSurface` 推进 `PetInstance` 状态；宿主把实例快照映射到透明窗口。每只宠物不单独启动进程，资源由角色定义共享。

角色加载失败只影响该目录；刷新时先完成校验，再以不可变引用替换索引，旧定义继续服务现存实例。所有数量创建调用同一服务并受可见软警告和可配置硬上限保护。默认以屏幕工作区底部为支撑，显示器断开时通过世界表面把实例放回可用区域。

## 验证

先用核心单元测试证明 3×3 帧、配置回退、物理状态、delta 限制和实例隔离，再用 Windows 手工会话验证透明区域点击穿透、宠物实体拖拽、不抢焦点、托盘退出和 1/10/50/100 档。任何未实际运行的桌面能力都记录为未验证。

这份草案需在开始 M1 编码前获得确认；确认后再写逐任务实施计划。
