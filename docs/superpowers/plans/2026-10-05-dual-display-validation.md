# 双显示器桌面补验计划

用户已接入第二屏，本轮恢复原先暂缓的双屏验收。保留单宿主/每宠一窗口结构，不修改系统显示配置，不运行会改写真实角色/用户设置的旧 smoke。

| 任务 | 修改范围与依赖 | 验证与完成条件 |
| --- | --- | --- |
| 1. 独立桌面入口 | `tools/DesktopDisplaySmoke`、`scripts/desktop-display-smoke.ps1`；复用生产 `PetWindow`、Core session、cache、surface 和应用 DPI 初始化 | 记录实际双屏 bounds/work area、原生窗口 DPI、OS、进程架构；逐屏检查生成掉落、行走/跳跃、透明点击/实体命中、真实跨屏鼠标拖拽、不激活、释放落地、两角色/缩放和清理；失败返回非零，缺硬件/锁屏返回未验证 |
| 2. 修复复现缺陷 | 仅修改证据涉及的 App DPI/显示适配/坐标转换和必要 Core 恢复路径 | 先取得真实失败或新增 Core 失败测试，再做最小修复；复测相同断言；不得削弱断言以宣告通过 |
| 3. 资源与回归 | 同一 smoke 多次创建/清空两屏窗口；现有 Core/build | 记录实际实例数、CPU/内存/句柄及 USER/GDI，完成后测试窗口和缓存归零；不重复 100 只长时间压力测试 |
| 4. 报告与交接 | `docs/TESTING.md`、`docs/STATUS.md`、独立双屏报告 | 逐项区分真实通过、代码/核心验证和未验证；未执行的负坐标、物理拔插、睡眠、任务栏变化保持未验证。新鲜构建/测试通过后本地提交 |

测试使用可见的自有探针窗口，不读取截图/用户窗口内容、不移动现有窗口、不保存用户设置。鼠标在 `finally` 松开并恢复位置。测试可暂时覆盖少量桌面区域，按串行运行，避免两个桌面工具争抢鼠标。
