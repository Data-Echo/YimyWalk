## 2. 产品目标

这是一个老式风格的桌面2D宠物软件，也是一套数据驱动的桌宠引擎，而不是只服务某个固定角色的专用程序。

用户应能把一张符合约定的3×3透明PNG放入角色目录，立即获得可以发呆、左右走、跳跃、坠落、被拖拽和说话的角色，不需要写代码、XML或脚本。

同一个角色模板可以创建多个独立实例，也可以同时加载不同角色。必须以1、10、50、100只为基础测试档位；100不是产品永久上限，但“可继续添加”不等于物理上无限，也不允许不受控制地耗尽资源。

宠物应能在桌面活动，落到屏幕工作区底部或可识别的窗口顶部，从屏幕上方掉下来，被鼠标拎起和抛出。后续增加饥饿、偷吃图标的趣味表现、事件对话、简单社交和可选繁殖。

基本原则：角色制作门槛低、动作与角色分离、资源尽量共享、桌面操作不被妨碍、趣味行为不得破坏用户数据。

## 4. 逻辑分层

按职责组织以下模块，实际文件名和项目数量可适应上游结构，不要求先建一堆空工程：

- PetEngine：实例状态、行为选择、移动、重力、碰撞和时间推进。
- PetRenderer：精灵、透明显示、缩放、翻转、粒子及气泡呈现。
- CharacterLoader：角色目录、3×3切图、配置、台词、校验与缓存。
- DesktopIntegration：Windows窗口、显示器、工作区、应用事件和图标能力。
- InteractionSystem：点击、拖拽、右键菜单、喂食、对话与趣味互动。
- AppHost/Settings：托盘、管理界面、配置、存档、日志和生命周期。

核心逻辑应可在不创建真实桌面窗口的情况下测试。通过少量必要接口替换时钟、随机源、显示器与桌面信息，不要在第一版引入插件市场、远程服务、通用脚本运行时或复杂微服务设计。

角色定义与实例分离，行为规则与贴图表现分离。Windows平台代码隔离，但暂不编写没有使用者的macOS/Linux空实现。

启动时扫描角色目录；管理界面提供重新扫描/重新加载入口。第一版手动刷新即可，不必为了自动监听而增加复杂性。重新加载要原子替换资源，失败时保留上一份可用角色；不得让现存实例访问已释放的图片。

开发时支持工作区 Characters。发行时明确可写的用户角色目录并提供“打开角色目录”；不要假定程序安装目录可写。可以提供明确的便携模式，但不要混淆内置只读素材与用户编辑文件。

## 6. 3×3精灵图标准

sprite.png 是带透明信息的PNG。图片宽度和高度分别能被3整除，切成3列3行、大小完全相同的9格。允许不同单格尺寸，不强制64×64，也不强制宽高相等。

推荐示例：单格64×64，整图192×192；也支持整图96×96、384×384及其他合法尺寸。

按从左到右、从上到下的顺序，索引从0开始：

第一排：0 发呆1；1 发呆2；2 发呆3。
第二排：3 走路1；4 走路2；5 走路3。
第三排：6 起跳；7 滞空/最高点；8 下落。

发呆与走路可循环。第二排统一画朝右，朝左由程序水平镜像。

第三排不是连续循环动画：上升用6，接近最高点时短暂用7，下降用8。直接从屏幕上方生成或被松手下落时，不强行先播放起跳。落地返回发呆或走路，可附带程序化缓冲效果。

默认脚底锚点为单格坐标的(0.5×宽度, 0.9×高度)。所有帧使用一致的锚点，翻转围绕该锚点处理。不要逐帧自动裁剪后导致人物位置抖动。视觉缩放、鼠标命中与物理位置必须使用一致的坐标转换。

默认按像素画显示，优先最近邻采样；允许用户选择适合非像素素材的平滑缩放。保留真实Alpha透明，不得随意用某种角色颜色作为透明色。

这只是受RPG风格小人启发的自定义格式，不宣称可以直接兼容所有RPG Maker角色图。

对文件损坏、尺寸不合法、过大像素数、全透明图、越界帧和配置错误给出清楚提示。为文件体积、解码尺寸、台词长度等设合理上限；单个坏角色包不能拖垮整个程序。

## 7. 可选角色配置和动作扩展

定义带 schemaVersion 的配置格式，提供真实可加载的示例与校验。字段单位必须写清楚。缺失字段补默认值；无效字段按文档给出错误或回退，不允许静默产生NaN、负尺寸或无限计时器。

以下是建议的基础示例，可依据实现调整，但最终代码、示例与文档必须一致：

{
  "schemaVersion": 1,
  "displayName": "示例小猫",
  "scale": 1.0,
  "anchor": { "x": 0.5, "y": 0.9 },
  "animation": { "idleFps": 3, "walkFps": 8 },
  "movement": {
    "walkSpeed": 60,
    "jumpSpeed": 450,
    "gravity": 1500,
    "maxFallSpeed": 1500
  },
  "behavior": {
    "idleSecondsMin": 2,
    "idleSecondsMax": 8,
    "hungerIncreasePerMinute": 0.01,
    "speechCooldownSeconds": 45
  }
}

上述速度和重力以定义好的逻辑坐标单位/秒及单位/秒²表示。hunger 范围为0到1，0不饿、1最饿。配置优先级建议为：内置默认→角色配置→用户对该角色的覆盖；临时实例调整不回写作者原文件。

核心路径稳定后，支持可选额外动作，例如吃东西、睡觉、被拖拽、开心和落地。actions.png 必须有明确配置声明单格尺寸、动作对应帧、速度、是否循环和锚点；不能仅凭额外图片“猜”动作。

基础9格格式保持长期可用。高级动作缺失时，使用基础帧加位移、轻微缩放、抖动、气泡或粒子完成表现，不要求角色作者为了系统新增动作重新画图。

对不适合镜像的角色，可在高级配置中提供独立左向帧；不增加基础角色包制作负担。角色包只含数据与媒体，不加载任意DLL、脚本、Shell命令或远程资源。解析继承自上游的XML时禁用外部实体和外部资源解析。

## 8. 多实例与资源管理

CharacterDefinition 保存角色的只读配置、帧映射、台词及共享图片。PetInstance 仅保存自己的实例ID、角色引用、位置、速度、朝向、动作状态、动画时间、饥饿/心情/精力等数值、冷却、目标和随机状态。

同角色100只应尽量共享图片与只读定义，不加载100份相同纹理。不得把可变饥饿值或动作计时器放在共享角色定义里。

提供单只、10只、50只、100只和自定义数量创建。创建后默认从选定显示器上边缘外随机位置掉下，形成“宠物雨”；避免所有实例完全重叠，也避免大批生成阻塞UI。测试报告必须注明实际活跃数量，而不是排队中的数量。

提供删除单只、删除某角色全部实例、一键清空、暂停/继续、全部静音和紧急隐藏/恢复。退出时停止后台活动并释放托盘、窗口、钩子和计时器。

“无限创建”实现为可配置数量与资源保护，不是无限递归生成。设置可见的软警告和可配置硬上限，不把100硬编码为永久最大值。达到上限时应有明确反馈。

统一或共享可共享的计时与桌面查询；不要每帧为每只宠物扫描整个桌面。图片和系统句柄有明确生命周期。删除实例后取消任务、解除事件订阅并释放专属资源，共享资源仍被其他实例使用时不得提前释放。

## 9. 移动、物理和输入

使用明确状态机或同等清晰的有限状态结构，至少支持Idle、Walk、Jump、Fall、Dragged。再按需要加入Eat、Sleep、Interact；说话等表现尽量作为可叠加状态，不破坏运动状态。

行为优先级应明确，例如拖拽优先于自主运动；失去支撑应进入坠落；进食不能继续追逐另一个目标。为卡住、目标失效、超时和中断设计恢复路径，避免永久停在某个动作。

时间推进与渲染帧率解耦。使用单调时钟和可控时间步长，限制休眠恢复后的巨大delta，防止穿过地面或飞出屏幕。不要每帧重新创建随机源。

左右走、随机停顿、主动跳跃、重力下落、落地缓冲和边界处理都要真实可用。跳跃和坠落依赖位置与速度变化，不只是播放两张图片。

拖拽时跟随鼠标并暂停自主控制；释放时恢复物理。可根据近期鼠标运动计算抛掷速度，但要限幅。窗口失去捕获、鼠标松开和程序切换时不得永久卡在Dragged状态。

默认以显示器工作区底部作为地面，不能假定主显示器左上角始终为(0,0)。支持负坐标副屏、不同缩放比例、跨屏拖动、任务栏位置/自动隐藏变化、显示器断开与休眠恢复。

明确逻辑单位与物理像素转换，避免重复缩放。显示器消失时把宠物安全放回可用区域。重启时修正旧显示布局下的离屏位置。

窗口顶部落脚通过DesktopIntegration提供的可用表面处理，排除本程序、隐藏、最小化、不可交互或已失效的窗口；考虑遮挡，至少不让宠物站在明显不可见的窗口顶边。窗口移动、缩放、关闭后应跟随、重新落地或坠落。

第一阶段可只验证屏幕地面，窗口落脚在后续阶段完善。无法正确识别的特殊窗口安全降级，不宣称支持所有应用。

默认不移动、关闭、最小化或控制用户的其他应用窗口。

## 10. 自主行为与趣味数值

在状态机之上增加轻量需求驱动，而不是把全部行为写成无约束随机if。

至少实现饥饿与无聊；逐步加入心情、精力、社交和好奇。数值只用于轻度行为倾向，不做复杂付费养成，不因用户不照顾宠物而删除角色或处罚用户。

示例闭环：发呆→无聊→散步或跳跃；饥饿→寻找可用食物→靠近→吃东西→饥饿下降→短暂满足；被点击→反馈；被拖拽→对应台词；精力低→休息。

行动需要适用条件、权重/优先级、持续时间和冷却；高频渲染不等于每帧重新决策。找不到或无法到达目标时要超时回退，不能让所有宠物同时争抢一个失效对象。

先实现“人工喂食”或程序生成的虚拟食物，让饥饿系统不依赖真实桌面图标能力。用户可以关闭饥饿或减慢增长。

缺少Eat/Sleep/Dragged专用图片时使用基础帧和程序化效果。不把完成这些玩法的前提变成“作者再画一整张动画”。

## 11. 对话、事件与外部应用反馈

自动对话采用靠近宠物的非模态气泡，不抢焦点，不要求用户不断关闭系统MessageBox。需要选择的交互可以由用户点击打开小面板。

同时100只宠物不能一起弹出100个气泡。实现全局限流、单宠物冷却、事件合并、过期丢弃和同时显示上限。提供对话频率、静音、勿扰和关闭自动气泡的设置。默认气泡不遮挡正常点击，并自动消失。

内置中文默认台词。dialogue.txt 使用UTF-8和分组格式，例如：

[idle]
……
你还在吗？
我去那边看看。

[hungry]
饿了。
那个图标看起来不错。

[created]
我来了。

[clicked]
怎么了？

[dragged]
轻一点。

[fall]
啊——

[ate_icon]
吃饱了。

[program_opened]
你又打开东西了。
这是干什么的？

没有台词文件、某组缺失或某组为空时回退到内置台词。忽略空行，明确注释和未知分组的处理，限制长度，文本只按普通文本渲染。

定义清晰事件，包括：
APP_STARTED、PET_CREATED、PET_CLICKED、PET_DRAGGED、PET_HUNGRY、PET_FELL、PET_ATE_ICON、PROGRAM_OPENED、PROGRAM_CLOSED、TIME_MORNING、TIME_NIGHT、IDLE_TOO_LONG。

明确区分桌宠软件自身启动与用户打开其他软件。外部应用识别默认关闭，由用户主动开启。只读取实现功能所需的有限应用标识/窗口事件，不读取键盘、文档正文、浏览器历史或屏幕内容，不默认保存窗口标题或完整路径。

优先使用合适的系统事件或低频共享检测，并处理权限不足、进程快速退出、多窗口和重复事件。若只能可靠检测前台切换，就使用单独的APP_FOCUSED等事件，不把“获得焦点”冒充“首次启动”。时间段台词依据系统本地时间触发并去重，休眠恢复时不补发大量过期事件。

外部事件与窗口落脚都必须可关闭；关闭应用反馈后停止不必要的相关监听，而不是仅隐藏气泡。角色可覆盖事件台词，没有角色台词时使用默认值。

不接入LLM，不要求API Key。将来需要智能对话时再单独设计，不为此先搭建联网基础设施。

## 12. 偷吃桌面快捷方式：视觉模式优先

这个玩法分为两个明确不同的模式，不得混为一谈。

A. 默认安全视觉模式，属于正式版基础玩法。

绝不删除、移动、改名或修改真实桌面文件，也不修改快捷方式指向的目标。先使用程序生成的虚拟图标/食物完整实现：寻找→靠近→抖动→图标分身向宠物移动→缩小消失→满足/打嗝反馈。

后续可在用户允许后，只读取得可访问快捷方式的图标或位置。无法取得真实位置时使用虚拟目标，不硬编码坐标，不伪造识别成功。图标读取不得执行快捷方式或解析到网络资源；不安全或不可用时用通用占位图标。

必须承认视觉能力边界：只把复制出来的图标吃掉，真实图标通常仍在原处。不能把“动画分身消失”写成“真实桌面图标已经隐藏”。没有可靠实现时，产品用语明确为叼走图标分身/偷吃图标影子。

不要用一块假壁纸或纯色矩形粗暴覆盖真实图标，也不要隐藏整个桌面、改注册表、注入Explorer或破坏点击来假装实现。若存在可靠且可恢复的单图标隐藏能力，另行记录并验证后再考虑加入，不能影响基础视觉模式交付。

虚拟图标应有可达性判断、占用/预定机制和超时；一个对象被吃掉后释放目标，避免多只宠物重复消费同一对象。

B. 可恢复的真实“暂存快捷方式”模式，仅为后续高级功能，默认关闭。

本轮先设计边界、恢复流程和沙盒测试；不要在开发过程中拿我的真实桌面文件做移动实验。真正触碰用户文件必须在后续实现中由用户单独启用并选定允许范围。

仅考虑用户明确允许的普通.lnk文件，不处理.exe、文件夹、文档、系统虚拟图标、未知文件类型或快捷方式目标文件。拒绝路径穿越、符号链接/重解析点绕过、网络位置和未授权路径；云同步桌面默认排除，不能忽略同步影响。

真实模式不是删除，而是移到受控的PetStomach暂存区。原型优先限制为同卷可恢复移动；无法保证时拒绝执行并退回视觉模式，不悄悄降级为危险的复制后删除。

移动前持久化操作日志，记录源路径、暂存路径、唯一ID、文件校验信息、状态及归属实例；采用可恢复的步骤处理移动与日志之间的崩溃窗口。实现单个吐回、全部吐回、启动恢复检查、权限失败和同名冲突处理。

恢复不能覆盖已存在的文件；发生冲突时保留暂存文件，让用户选择位置。仅恢复确实属于本程序记录且校验通过的内容。宠物被删除、一键清空、配置重置或卸载时，不能把暂存物一起清理掉，也不能让恢复入口丢失。

在临时测试目录验证断电/崩溃中断、重名、锁定、权限不足、重复恢复、篡改与部分失败。未达到恢复验收要求之前，不提供真实桌面启用入口。

## 13. 角色间互动及扩展玩法

核心性能和基础行为通过验收之后，再加入角色相遇、互相看一眼、简短对话、轻微避让或碰撞。可开关，不让大量宠物挤在一起导致物理失控。

需要邻居查询时采用空间分区等合理方法，避免实例数增长后每帧无节制地全量两两比较。不要为了趣味碰撞阻塞鼠标交互。

可选繁殖作为后续实验功能：特定角色相遇后有低概率生成新实例；默认关闭，有全局数量上限、生成速率限制、冷却、关闭入口和一键清空。不得形成失控的指数增长。

未来可支持角色自定义额外动作、更多台词和性格参数，但基础3×3角色始终拥有通用行为。

## 14. 托盘、管理界面和本地指令

默认启动后提供托盘入口和简洁的角色管理窗口，不需要复杂游戏主界面。管理界面使用简体中文，文案与逻辑适当分离，便于以后本地化。

应能看到角色预览、角色名称、实例数量，选择角色并创建指定数量；可调整显示大小、活动程度/移动速度、对话频率、音量/静音和所在显示器。

提供打开角色目录、刷新角色、暂停/继续、隐藏/恢复、关闭自动对话、手动喂食、删除实例、按角色删除、一键清空和退出。尚未实现的功能不得显示为可用按钮后点击无效。

宠物右键菜单提供当前实例相关操作。气泡和宠物窗口默认不抢焦点；用户明确打开设置时，设置窗口正常接收输入。透明区域应允许点击底下的桌面与应用，宠物实体区域可用于拖拽。另提供“宠物也完全点击穿透”的模式，并保留托盘恢复入口。

支持内部命令或等效调试入口，例如：
/create cat 100
/create slime 20
/delete-all cat
/clear
/pause
/resume

这些是软件自己的命令，不是把用户字符串直接交给Shell。验证参数、角色ID与数量，统一调用与UI相同的业务逻辑。不增加未经认证的网络控制服务。

默认不自动开机启动、不申请管理员权限、不打开外部网页、不自动下载新角色。全屏应用和勿扰模式下支持自动减少或暂停干扰，保留手动开关。全局热键不是必需项，避免抢占用户已有快捷键。

## 15. 本地配置、安全与恢复

持久化用户设置、已选角色和必要实例状态。使用可写用户数据目录；首次启动、无权限、损坏存档、角色被移除和显示器布局变化都要有安全回退。

保存采用原子替换或等效可靠方式；提供备份/版本迁移，不高频写盘。不要把临时动画帧和每次位置变化逐帧落盘。异常退出后可进入少量实例的安全恢复模式，避免重启又立即创建大量宠物导致反复崩溃。

运行时日志默认只记录必要错误和性能摘要，设定轮转/大小限制，不收集个人内容。调试用详细日志默认关闭。不得把密钥、真实桌面路径、完整进程路径或用户文件内容提交到仓库。

审查上游可能存在的联网下载、遥测、自启动和更新逻辑；发行版默认不得自动触发这些行为。角色包路径必须限制在允许范围，禁止借配置加载任意本地敏感文件或远程内容。

测试输入和恢复实验使用工作区/临时沙盒，不操作我的真实快捷方式、注册表或开机启动项。性能测试也应可中止，不自动运行无人值守的极端数量测试。

## 16. 性能与验收证据

以可配置帧率运行，默认可先选择30FPS，验证后提供更流畅模式。渲染、物理推进、行为决策和桌面扫描不必同频。不可见/暂停时减少不必要更新，高实例数量下优先减少非必要粒子与气泡。

在可用Windows环境下分别测试1、10、50、100只。记录机器CPU、内存、GPU/渲染方式、系统版本、屏幕数量与缩放、构建模式、角色尺寸、测试时长和实际实例数。

观测进程CPU、内存、窗口/系统句柄、适用时的GDI/USER资源、更新耗时、拖拽响应以及生成和清空后的释放情况。CPU百分比口径要说明。先做短测试筛查，再进行更长的稳定性测试；未执行的时长不能写成已经通过。

比较原版与改造版本时保持条件尽量一致。性能阈值依据真实基线提出，不能在没有测试机器的情况下保证“100只一定流畅”或编造精确CPU占用。

截图只能证明对应画面，不能代替点击穿透、焦点或长期资源稳定性测试。核心模拟基准也不能冒充完整Windows桌面性能测试。

如果当前是WSL、Linux、云环境或无桌面会话，先确认哪些Windows构建/运行能力可用。执行能运行的逻辑测试，生成明确的Windows复现步骤，将GUI结果标为未验证；不把编译成功当成功能通过，不通过削弱断言来获得全绿。

## 17. 测试范围

单元测试至少覆盖：3×3切图与索引；不同合法尺寸；无效/超大输入；默认配置合并；锚点与翻转；动作扩展回退；台词分组与回退；状态迁移；跳跃/坠落/落地；拖拽中断；delta上限；独立随机源；实例状态隔离；资源引用与清理；命令参数；气泡限流；饥饿与喂食；目标占用与失效；存档恢复和路径校验。

集成测试覆盖：新增一个只有sprite.png的角色后无需改代码就能使用；不同角色同时运行；同角色100实例共享资源；重新加载失败不破坏现存实例；批量创建和清空；虚拟食物完整消费流程；应用事件去重与监听关闭；损坏配置恢复。

Windows手动/可自动化验收覆盖：透明区域点击穿透；宠物命中与拖拽；不抢焦点；右键和托盘恢复；不同DPI；负坐标副屏；跨屏拖动；任务栏变化；窗口移动/最小化/关闭；显示器断开；锁屏和休眠恢复；全屏与勿扰；连续创建删除后的资源趋势；退出后无遗留活动。

真实快捷方式暂存仅在后续阶段做独立沙盒测试，不能作为普通测试套件的默认真实文件操作。

测试报告明确区分：通过、失败、跳过、未执行；给出命令、环境与关键输出位置。空测试、只测mock却未测实际适配、静态检查通过，不得包装成完整运行验证。

## 18. 分阶段实施与完成标准

按以下顺序推进，在当前会话和工具条件允许的范围内持续实现。每一阶段应留下能运行或能独立验证的结果，不要因为需求完整就同时铺开所有模块。

M0：建立可信基线。
完成工作区检查、上游获取与提交固定、许可/代码审计、构建尝试和决策记录。建立可复现命令。不能只交付文档，条件允许时立即进入M1。

M1：最小可玩桌宠。
完成单张3×3PNG加载、至少两个可替换的测试角色、发呆/走路/跳跃/坠落、拖拽/抛掷、基础透明显示、托盘和退出；可以创建1/10/50/100只及一键清空。先保证真实窗口中能活动，不用普通窗口里的动画冒充桌面宠物。

M2：形成可持续扩展的基础版本。
完成共享资源、独立实例状态、配置与角色刷新、DPI/显示器处理、窗口落脚、点击穿透/焦点修复、设置保存与恢复，并完成多实例基线观测。根据证据决定是否局部更换渲染/调度结构。

M3：完成核心趣味闭环。
完成饥饿/无聊、喂食、默认视觉吃图标、通用程序化动作、角色台词、事件气泡与限流、可关闭的外部应用反馈、基本额外动作支持。关闭外部权限后，核心玩法仍然可用。

M4：稳定化与可选扩展。
优先修复真实验收发现的问题，整理发布包和角色作者材料；稳定后加入轻量社交和实验性繁殖。真实快捷方式暂存只进入独立设计/沙盒验证，达到恢复标准且经过另外的用户启用流程后才开放；不阻塞基础版本发布。

本轮不要做：在线商店、账号登录、联网AI、付费功能、自动更新服务、自动开机启动、复杂角色绘图编辑器、3D角色、跨平台发行或无限制的角色脚本。

所有未完成项都保存在状态文档中，不静默从需求中删除。因某个外部接口暂时受阻时，优先完成不依赖它的闭环，不让整个项目停在空框架阶段。
